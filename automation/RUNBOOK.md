# 수집 실패 대응 런북 — D-minus 사전추적 (KOBIS·버즈)

> 2026-07-11 경보: `⚠️ 호프 D-4 (2026-07-11) 수집 전면 실패 — KOBIS·버즈 모두 무응답(6회 시도). 행 미기록 · 내일 회복 기대.`

## 1. 진단 — 왜 "전면 실패"였나

KOBIS(정부 박스오피스 API)와 버즈(소셜 WOM)는 **완전히 독립된 서비스**다.
둘이 동시에 죽을 확률은 매우 낮다. 독립된 두 소스가 함께 실패하면 원인은
거의 항상 **원격 API가 아니라 수집기 쪽 공통 지점**이다. 유력 순서:

| # | 원인 | 근거/특징 | 확인 방법 |
|---|------|-----------|-----------|
| 1 | 수집기 호스트의 이그레스/네트워크 (DNS·프록시·IP 화이트리스트·인증서) | "무응답=timeout"이지 HTTP 4xx/5xx가 아님 → 네트워크/DNS/멈춘 클라이언트 | 호스트에서 `curl -v https://www.kobis.or.kr` + 버즈 URL 직접 타격 |
| 2 | 공유 코드 경로 (단일 HTTP 세션/전역 예외로 6회 함께 사망) | 한 예외가 두 소스 루프를 같이 무너뜨림 | 코드에서 두 소스가 try/except를 공유하는지 확인 |
| 3 | 만료된 토큰/키 | 공유 시크릿 만료 시 두 인증 호출 동시 실패 | 키 만료일·회전 로그 확인 |
| 4 | (낮음) 날짜/휴일 가드 | 미확정 날짜를 실패로 오판 | 버즈까지 죽었으면 이건 아님 |

기존 파이프라인의 문제는 원인 자체보다 **실패를 다루는 방식**이었다:
- 두 소스를 **한 덩어리로 처리** → 한쪽 실패가 행 전체를 날림("행 미기록").
- 알림이 **원인(kind)을 안 남김** → timeout인지 인증오류인지 알 수 없어 "무응답"으로만 뭉뚱그림.
- 복구를 **사람("내일 회복 기대")에게 미룸** → 자동 백필 없음, 시계열에 구멍.

## 2. 처방 — `collect.js`가 바꾼 것

| 경보 증상 | 처방 |
|-----------|------|
| KOBIS·버즈 모두 무응답 | 두 소스 **독립 수집**(`Promise.all`, 각자 try/catch). 한쪽 6회 실패가 다른 쪽·행을 죽이지 못함 |
| 무응답(6회 시도) | `AbortController` 타임아웃 + **지수 백오프 + 지터**, 실패를 `timeout/http/network/empty/config`로 **분류** |
| 행 미기록 | 성공분만이라도 `status: ok\|partial\|failed` 로 **항상 upsert** → 구멍 없음 |
| 내일 회복 기대 | `--heal` 로 누락/실패 행 **자동 백필**. 회복을 사람이 기다릴 필요 없음 |

행은 `automation/out/rows_<title>.json` 에 날짜별로 누적(upsert)된다.
`partial/failed` 행은 다음 실행에서 자동으로 재수집·덮어쓰기된다.

## 3. 지금 2026-07-11 구멍 메우기

```bash
cd <repo>
cp automation/.env.example automation/.env   # 실제 키 채우기 (KOBIS_KEY / BUZZ_URL ...)
set -a && . automation/.env && set +a

# (a) 누락된 그 날짜만 백필
node automation/collect.js --backfill 2026-07-11

# (b) 또는 추적창 전체 구멍 자동 탐지·복구
node automation/collect.js --heal

# 결과 확인
cat automation/out/rows_호프.json
```

## 4. 매일 자동 실행 (권장: 수집 + 자가치유를 한 번에)

```bash
node automation/collect.js --run --heal
```

크론/CI 스케줄에 이 한 줄을 걸면: 오늘치를 수집하고, 이전에 실패/누락된 행이
있으면 같은 실행에서 백필한다. `--dry` 로 텔레그램 전송 없이 로컬 검증 가능.

종료 코드: `failed` 행이 남으면 `1`(부분성공은 `0`) → CI가 실패로 인지.

## 5. 아직 채워야 할 실제 연결점 (플레이스홀더)

이 수집기의 **복원력 로직은 완결**돼 있고, 아래만 실제 값으로 연결하면 된다:

- `KOBIS_KEY` — KOBIS 오픈API 키. 개봉 전 "예매율"이 오픈API가 아닌 별도 소스라면 `KOBIS_BASE`/`collectKobis` 를 그 소스에 맞춰 교체.
- `BUZZ_URL` (+ 선택 `BUZZ_KEY`) — 실제 버즈 소스의 요청 형식. `{title}`·`{date}` 치환.
- `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` — 기존 경보와 같은 봇/채팅.
- `subjects.json` — 추적 작품 목록. 현재 `호프 (openDt 2026-07-15)` 로 D-4=2026-07-11 이 맞게 세팅됨.

> 참고: 이 저장소는 원래 대시보드(`index.html`)가 `automation/out/` 파이프라인 산출물을
> 참조하도록 설계돼 있었으나 `automation/` 폴더 자체가 커밋된 적이 없었다. 이 디렉터리가
> 그 빠져 있던 조각이다. **이미 다른 곳(사설 repo·로컬 크론·서버)에서 도는 실제 수집기가
> 있다면, 위 4개 처방(독립 수집 / 실패 분류 / partial 행 / 자동 백필)을 그 코드에 이식하면 된다.**
